# App Store 1.0 Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the App Review gaps (account deletion, report/block, legal links, dead push options, native Apple sign-in, reviewer access, iPhone-only) and cut 1.0.0.

**Architecture:** Two migrations (account-deletion FKs + `delete_account_data`; reports/blocks + block filtering), two edge functions (`delete-account`, `notify-report`) on the existing SMTP/denomailer helpers, client screens for delete account, report/block, blocked people and admin reports, plus marketing-site legal pages.

**Tech Stack:** Expo Router 57 / React Native / react-native-web, Supabase (Postgres, pgTAP, Deno edge functions), vitest + @testing-library/react, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-22-app-store-1-0-design.md`

## Review Focus

1. **Deleting a host who is the only host of a club with other members** → the longest-tenured member becomes host; deleting the only member deletes the club. pgTAP in Task 1.
2. **Deleting someone holding a future seat in a full game with a waitlist** → the seat is offered to the next person exactly as a normal cancel would. pgTAP in Task 1.
3. **Deleting someone who authored a board post with others' replies** → post and its replies are gone; no orphan reply appears as a top-level post. pgTAP in Task 1.
4. **A blocked person's content across every surface** (thread messages, board feed, post replies, club chat, media, my-threads preview) is hidden from the blocker, and neither can open a DM to the other. pgTAP in Task 4.
5. **A non-admin calling `fetch_reports` / `resolve_report`, or reporting content they cannot read** → 42501. pgTAP in Task 4.

### Task 2: `delete-account` edge function

**Files:** create `supabase/functions/delete-account/index.ts`, `supabase/functions/delete-account/apple.ts`, `supabase/functions/delete-account/__tests__/*.test.ts` (follow `send-club-invite/__tests__` conventions and how they run under vitest); `supabase/config.toml` `[functions.delete-account]` if other functions declare entries; document new secrets in the `supabase/.env.prod` example comment block **only if that file is tracked** (check `git ls-files`).

**Consumes:** Task 1 `delete_account_data`.

**Produces:** POST `/delete-account` body `{ apple_authorization_code?: string }`, auth header required → `200 { deleted: true }`; `401` without a valid user. `apple.ts` exports `makeClientSecret({teamId,keyId,privateKey,clientId,now})` (ES256 JWT, `iss` team, `sub` client id, `aud` `https://appleid.apple.com`, ≤ 5 min expiry) and `revokeAppleToken(code, env, fetchImpl)` (token exchange then `/auth/revoke` with `token_type_hint=refresh_token`; resolves `{revoked:boolean, reason?}`, never throws).

- [ ] **Step 1: Failing tests:** client secret has correct header/claims and verifies with the public key of a test keypair; revoke happy path calls both endpoints with the right form bodies; token-exchange failure → `{revoked:false}`; handler without auth → 401; handler with auth calls RPC, removes returned storage paths grouped by bucket, then `auth.admin.deleteUser`; Apple failure still deletes.
- [ ] **Step 2–4:** FAIL → implement (inject supabase client + fetch for tests, like the existing functions) → pass + full `npm test`.
- [ ] **Step 5: Commit** `feat(functions): delete-account with Apple token revocation`.
